[DataRobot Agent Templates](https://github.com/datarobot-community/datarobot-agent-templates).

# DataRobot Agentic AI + Neo4j GraphRAG Integration

This repository contains the implementation of an intelligent agent developed within the **DataRobot GenAI (DRUM)** framework and orchestrated via **LangGraph**. The agent is natively integrated with a **Neo4j** graph database to perform GraphRAG (Graph-based Retrieval-Augmented Generation) operations.

---

## 🛠️ Project Architecture

The application is structured as a multi-package monorepo managed via `uv`.

* `agent/`: Contains the LangGraph agent logic, system prompts, and Custom Tools.
* `infra/`: Pulumi code for infrastructure deployment on DataRobot Cloud.
* `mcp_server/`: Configuration for Model Context Protocol servers.

---

## 📦 Dependency Configuration (`agent/pyproject.toml`)

The libraries required to communicate with Neo4j have been injected into both the core project dependencies and the `uv` override constraints to guarantee runtime compatibility within the DataRobot environment:

```toml
[project]
dependencies = [
    # ... core datarobot dependencies ...
    "langchain-neo4j>=0.1.0",
]

[tool.uv]
override-dependencies = [
    "langchain-neo4j>=0.1.0",
    "neo4j>=5.0.0",
]

```

To sync the local virtual environment, run:

```bash
uv sync

```

## 📝 Developed Components

### 1. The Custom Tool (`agent/neo4j_tool.py`)

A standard LangChain tool that handles the lazy loading of the `Neo4jGraph` instance. It accepts Cypher queries generated by the LLM and returns the database records as a string. If a syntax error occurs, it returns the explicit database error back to LangGraph to enable agent self-correction.

### 2. Tool Registration (`agent/register.py`)

The tool is dynamically injected into the agent pipeline by appending it directly to the tools list before the framework initialization:

```python
tools = workflow_tools + mcp_tools + [query_knowledge_graph]

```

### 3. Agent Logic & Prompts (`agent/agent.py`)

The application implements a two-node sequential LangGraph workflow (`planner_node` -> `writer_node`). The system prompt for the `planner_agent` has been reinforced to strictly enforce the usage of the graph database when handling relational data:

```text
You are a content planner with direct access to an enterprise Neo4j Knowledge Graph. 

CRITICAL OPERATIONS RULE: If the user asks about entities, actors, movies, directors, people, or relationships, you MUST immediately formulate a valid Cypher query and execute it using the 'query_knowledge_graph' tool. Do NOT ask the user for clarifications, choices, or permissions. Always query the graph database first to fetch the ground-truth data.

```

## 🚀 How to Run Local Tests (Zero Cost)

The infrastructure simulates the DataRobot production cloud environment locally using the DRUM adapter.

### Step 1: Start the Development Server (Terminal Tab 1)

Inside the `agent/` folder, spin up the local Flask prediction server on port `8842`:

```bash
python3 dev.py

```

### Step 2: Query the Agent via CLI (Terminal Tab 2)

Send an interactive prompt to verify that the agent successfully translates natural language into Cypher, queries Neo4j Labs, and outputs the final response:

```bash
python3 cli.py execute --user_prompt "Use the query_knowledge_graph tool to find which movies Christopher Nolan directed in our database."

```

### 🔍 Verification of Success in Server Logs

In the `dev.py` terminal window, you can verify successful execution by checking that:

1. The server logs the JSON payload containing the structured Cypher query (e.g., `MATCH (p:Person {name: 'Christopher Nolan'})-[:DIRECTED]->(f:Film)...`).
2. The server responds with an HTTP status code of **`200 OK`**, confirming that the remote connection to Neo4j Labs completed successfully and returned data to the agent.
